# Data Model: Vehicle Sticker Request System

**Feature**: Vehicle Sticker Request System
**Branch**: `feat/vehicle-sticker-request`
**Date**: 2025-10-20

## Overview

This document defines the data model for the vehicle sticker request feature. The model supports multiple vehicles per submission, document storage, sticker quota management, and request lifecycle tracking.

## Entities

### 1. sticker_requests (New Table)

Primary table for storing vehicle sticker request data.

**Purpose**: Track individual vehicle sticker requests through their lifecycle from submission to approval/rejection.

**Table Schema**:

```sql
CREATE TABLE sticker_requests (
  -- Primary Key
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),

  -- Foreign Keys
  household_id UUID NOT NULL REFERENCES households(id) ON DELETE CASCADE,
  resident_id UUID NOT NULL REFERENCES residents(id) ON DELETE SET NULL,
  tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,

  -- Vehicle Information
  vehicle_plate_number VARCHAR(15) NOT NULL,
  vehicle_make VARCHAR(50) NOT NULL,
  vehicle_model VARCHAR(50) NOT NULL,
  vehicle_color VARCHAR(30) NOT NULL,
  vehicle_year INTEGER NOT NULL CHECK (vehicle_year >= 1900 AND vehicle_year <= EXTRACT(YEAR FROM CURRENT_DATE)),
  registered_to VARCHAR(100) NOT NULL,

  -- Sticker Type
  sticker_type VARCHAR(20) NOT NULL CHECK (sticker_type IN ('resident', 'beneficial_user')),

  -- Document URLs (Supabase Storage paths)
  official_receipt_url TEXT NOT NULL,
  cert_registration_url TEXT NOT NULL,
  vehicle_photo_url TEXT,

  -- Request Metadata
  request_number VARCHAR(10) UNIQUE, -- e.g., "STK-000123" (generated by trigger)
  status VARCHAR(20) NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'approved', 'rejected', 'cancelled')),

  -- Timestamps
  submitted_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  reviewed_at TIMESTAMP WITH TIME ZONE,
  created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),

  -- Indexes
  CONSTRAINT unique_household_plate UNIQUE (household_id, vehicle_plate_number)
);

-- Indexes for performance
CREATE INDEX idx_sticker_requests_household ON sticker_requests(household_id);
CREATE INDEX idx_sticker_requests_resident ON sticker_requests(resident_id);
CREATE INDEX idx_sticker_requests_status ON sticker_requests(status);
CREATE INDEX idx_sticker_requests_submitted_at ON sticker_requests(submitted_at DESC);

-- Updated_at trigger
CREATE TRIGGER update_sticker_requests_updated_at
  BEFORE UPDATE ON sticker_requests
  FOR EACH ROW
  EXECUTE FUNCTION update_updated_at_column();

-- Request number generation trigger (auto-increment with prefix)
CREATE SEQUENCE sticker_request_number_seq START 1;

CREATE OR REPLACE FUNCTION generate_sticker_request_number()
RETURNS TRIGGER AS $$
BEGIN
  NEW.request_number := 'STK-' || LPAD(nextval('sticker_request_number_seq')::TEXT, 6, '0');
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER generate_sticker_request_number_trigger
  BEFORE INSERT ON sticker_requests
  FOR EACH ROW
  EXECUTE FUNCTION generate_sticker_request_number();
```

**Field Descriptions**:

| Field                   | Type         | Nullable | Description                                            |
| ----------------------- | ------------ | -------- | ------------------------------------------------------ |
| `id`                    | UUID         | No       | Primary key, auto-generated                            |
| `household_id`          | UUID         | No       | Reference to household making request                  |
| `resident_id`           | UUID         | No       | Reference to resident who submitted request            |
| `tenant_id`             | UUID         | No       | Reference to village/tenant                            |
| `vehicle_plate_number`  | VARCHAR(15)  | No       | License plate number                                   |
| `vehicle_make`          | VARCHAR(50)  | No       | Vehicle manufacturer (e.g., "Toyota")                  |
| `vehicle_model`         | VARCHAR(50)  | No       | Vehicle model (e.g., "Camry")                          |
| `vehicle_color`         | VARCHAR(30)  | No       | Vehicle color                                          |
| `vehicle_year`          | INTEGER      | No       | Year of manufacture (1900-current year)                |
| `registered_to`         | VARCHAR(100) | No       | Legal owner name on registration                       |
| `sticker_type`          | ENUM         | No       | "resident" or "beneficial_user"                        |
| `official_receipt_url`  | TEXT         | No       | Supabase Storage URL for OR document                   |
| `cert_registration_url` | TEXT         | No       | Supabase Storage URL for CR document                   |
| `vehicle_photo_url`     | TEXT         | Yes      | Supabase Storage URL for optional photo                |
| `request_number`        | VARCHAR(10)  | No       | Human-readable request ID (e.g., "STK-000123")         |
| `status`                | ENUM         | No       | Current status: pending, approved, rejected, cancelled |
| `submitted_at`          | TIMESTAMP    | No       | When request was submitted                             |
| `reviewed_at`           | TIMESTAMP    | Yes      | When admin approved/rejected request                   |
| `created_at`            | TIMESTAMP    | No       | Record creation timestamp                              |
| `updated_at`            | TIMESTAMP    | No       | Last update timestamp                                  |

**Business Rules**:

1. One request per vehicle plate number per household (UNIQUE constraint)
2. Vehicle year cannot be in the future
3. Vehicle year must be 1900 or later (reasonable minimum)
4. Status can only be: pending, approved, rejected, cancelled
5. Official Receipt and Certificate of Registration are mandatory
6. Vehicle photo is optional

**State Transitions**:

```
pending → approved (by admin)
pending → rejected (by admin)
pending → cancelled (by resident)
approved → cancelled (if sticker returned/revoked)
rejected → [terminal state]
cancelled → [terminal state]
```

## Validation Rules

### At Form Level (Client-Side)

**Vehicle Data**:

```typescript
{
  plateNumber: required, max 15 chars, alphanumeric + hyphens
  make: required, max 50 chars
  model: required, max 50 chars
  color: required, max 30 chars
  year: required, integer, 1900 <= year <= current year
  registeredTo: required, max 100 chars
  stickerType: required, enum ["resident", "beneficial_user"]
}
```

**File Uploads**:

```typescript
{
  officialReceipt: required, File, max 5MB, types: [PDF, JPG, PNG]
  certRegistration: required, File, max 5MB, types: [PDF, JPG, PNG]
  vehiclePhoto: optional, File, max 5MB, types: [JPG, PNG]
}
```

**Multi-Vehicle**:

```typescript
{
  vehicles: array, min 1, max 10
  totalVehicles <= (household.sticker_quota - currentStickerCount)
}
```

### At Database Level (Server-Side)

**Check Constraints**:

- `vehicle_year >= 1900 AND vehicle_year <= EXTRACT(YEAR FROM CURRENT_DATE)`
- `sticker_type IN ('resident', 'beneficial_user')`
- `status IN ('pending', 'approved', 'rejected', 'cancelled')`
- `sticker_quota >= 0`

**Unique Constraints**:

- `(household_id, vehicle_plate_number)` - prevents duplicate requests for same plate
- `request_number` - ensures unique request numbers

**Foreign Key Constraints**:

- `household_id` references households(id) ON DELETE CASCADE
- `resident_id` references residents(id) ON DELETE SET NULL
- `tenant_id` references tenants(id) ON DELETE CASCADE

## Row-Level Security (RLS) Policies

**Supabase RLS policies for sticker_requests table**:

```sql
-- Enable RLS
ALTER TABLE sticker_requests ENABLE ROW LEVEL SECURITY;

-- Policy: Residents can view their own household's requests
CREATE POLICY "Residents can view own household requests"
ON sticker_requests
FOR SELECT
TO authenticated
USING (
  household_id IN (
    SELECT household_id
    FROM residents
    WHERE user_id = auth.uid()
  )
);

-- Policy: Residents can insert requests for their own household
CREATE POLICY "Residents can create requests for own household"
ON sticker_requests
FOR INSERT
TO authenticated
WITH CHECK (
  household_id IN (
    SELECT household_id
    FROM residents
    WHERE user_id = auth.uid()
  )
  AND resident_id IN (
    SELECT id
    FROM residents
    WHERE user_id = auth.uid()
  )
  AND status = 'pending'
);

-- Policy: Residents can cancel their own pending requests
CREATE POLICY "Residents can cancel own pending requests"
ON sticker_requests
FOR UPDATE
TO authenticated
USING (
  household_id IN (
    SELECT household_id
    FROM residents
    WHERE user_id = auth.uid()
  )
  AND status = 'pending'
)
WITH CHECK (
  status = 'cancelled'
);

-- Policy: Admins can view all requests (for future admin panel)
CREATE POLICY "Admins can view all requests"
ON sticker_requests
FOR SELECT
TO authenticated
USING (
  auth.jwt() ->> 'role' = 'admin'
);

-- Policy: Admins can update request status (for future admin panel)
CREATE POLICY "Admins can update request status"
ON sticker_requests
FOR UPDATE
TO authenticated
USING (
  auth.jwt() ->> 'role' = 'admin'
)
WITH CHECK (
  auth.jwt() ->> 'role' = 'admin'
);
```

## Quota Calculation Logic

**Total Sticker Count for Household**:

```sql
SELECT COUNT(*)
FROM sticker_requests
WHERE household_id = :household_id
  AND status IN ('pending', 'approved');
```

**Remaining Quota**:

```sql
SELECT (
  (SELECT sticker_quota FROM households WHERE id = :household_id) -
  (SELECT COUNT(*) FROM sticker_requests
   WHERE household_id = :household_id
   AND status IN ('pending', 'approved'))
) AS remaining_quota;
```

**Business Logic**:

- `approved` stickers count against quota (active stickers)
- `pending` requests count against quota (prevents over-requesting)
- `rejected` and `cancelled` do NOT count against quota
- When sticker is revoked, status changes to `cancelled`, freeing up quota

## Data Flow

### Create Sticker Request Flow

```
1. User fills form → VehicleFormData[] (client state)
2. User clicks Submit → Validate against household quota
3. For each vehicle:
   a. Upload officialReceipt to Supabase Storage → get URL
   b. Upload certRegistration to Supabase Storage → get URL
   c. Upload vehiclePhoto (if exists) to Supabase Storage → get URL
4. For each vehicle:
   a. INSERT into sticker_requests with document URLs
   b. Trigger generates request_number automatically
5. Collect all request IDs
6. Show success toast with request numbers
7. Redirect to dashboard
```

### Quota Check Flow

```
1. Component mounts → Fetch household data (includes sticker_quota)
2. Fetch current sticker count (approved + pending)
3. Calculate remaining = quota - (approved + pending)
4. Display quota UI: "X of Y stickers used"
5. On vehicle add:
   a. Check if vehiclesArray.length < remaining
   b. If yes: allow add
   c. If no: show error "Quota exceeded"
6. On form submit:
   a. Server-side quota check (security)
   b. Prevent over-quota submissions
```
